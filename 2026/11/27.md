## 分かったこと

### Twitterのデータモデリング
- 主キーは列名の前に * を付ける
- 外部キーは label に FK(users) と書く。型は指している先の id と同じ bigint にする
- ツイートの本文は not null。本文が空のツイートはありえないから
- null か not null かは、users でも tweets でも「行ができた瞬間に値が入っているか」で決まる
- 列名に text は使わない。型の名前と同じで紛らわしいので content にした

### React 1：keyは行の「名札」
- Reactは名前や中身ではなく、`key` だけで「前回のどの行か」を見分けている
- 名札を配列の番号（index）にすると、消したときにずれる

```
【keyが番号のとき】taroを削除

 削除前              削除後
 key0 : taro         key0 : jiro    ← Reactは「0番はまだいる」と思い
 key1 : jiro    →    key1 : saburo     taroの行を使い回す
 key2 : saburo       （key2が消えた扱い）

 結果：jiroの行なのに、入力欄にtaroが残る
```

```
【keyがidのとき】taroを削除

 削除前              削除後
 a1 : taro           （a1が消えた）  ← 正しく「taroが消えた」と伝わる
 b2 : jiro      →    b2 : jiro
 c3 : saburo         c3 : saburo

 結果：ずれない
```

- だから `key={user.id}` のように、その人に固定の値を名札にする

### React 2：再レンダリングされるタイミングは3つ
| タイミング | 例 |
|---|---|
| 自分のstateが変わった | UserRowの入力欄に打つ → そのUserRowだけ |
| 親が再レンダリングされた | UserListが描き直される → UserRowも全部 |
| propsが変わった | 親のstateが変わって、渡す値が変わる |

### React 3：stateを置く場所で、描き直される範囲が変わる

```
【直す前】追加欄のstateがUserListにある

 UserList（newUserNameを持つ）  ← 描き直し
  ├─ UserRow taro              ← 描き直し（無駄）
  ├─ UserRow jiro              ← 描き直し（無駄）
  └─ 入力欄 + 追加ボタン
```

```
【直した後】AddUserFormに切り出した

 UserList                      ← そのまま
  ├─ UserRow taro              ← そのまま
  ├─ UserRow jiro              ← そのまま
  └─ AddUserForm（newUserNameを持つ）  ← ここだけ描き直し
```

- stateは、それを使う一番小さいコンポーネントに置く

### React 4：useEffectは「いつ実行するか」を決められる
- コンポーネントの中に直接書いた処理は、描き直されるたびに毎回実行される
- `setInterval` を直接書いたら、描き直しのたびにタイマーが増えて、秒数がどんどん速くなった
- `useEffect(処理, [見張る値])` で、実行するタイミングを絞れる

| 後ろの書き方 | 実行されるタイミング |
|---|---|
| `[]` | 最初の表示の1回だけ |
| `[time]` | 最初の表示と、timeが変わるたび |
| 何も書かない | 描き直されるたび毎回 |

- `[time]` の中に `setInterval` を入れても、timeが変わるたびにタイマーが増えてだめだった。タイマーの開始は `[]` に入れる
- useEffectの中身は、画面を描き終わった後に実行される

```
【最初の表示】              【1秒ごと】
 Timer Rendering1            Timer Rendering1
 Timer Rendering2            Timer Rendering2
 （画面を描く）              （画面を描く）
 Timer useEffect  ← 最後     ※useEffectは出ない（[]なので1回だけ）
```

- `setTime((prevTime) => prevTime + 1)` は、最新の値を受け取って+1する書き方
- console.logが2回ずつ出るのはStrictModeのせいで、バグではない
