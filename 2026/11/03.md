### 分かったこと
#### コマンドをつなぐ記号

| 記号 | 意味 | 例 |
|---|---|---|
| `A && B` | A が成功したら B | `grep -q error app.log && echo "エラーあり"` |
| `A \|\| B` | A が失敗したら B | `cat memo.txt \|\| echo "ファイルがない"` |
| `A ; B` | A の成否に関係なく B | `touch a.txt; touch b.txt; ls` |
| `A &` | A をバックグラウンドで動かし、すぐ次へ | `sleep 1000 &` |
| `A \| B` | A の出力を B の入力に渡す（パイプ） | `cat app.log \| grep error` |

- 「成功・失敗」は終了コードで判定される。`echo $?`で直前のコマンドの終了コードを確認でき、0 が成功、それ以外が失敗。
- `&`（1個）と`&&`（2個）は役割が全く違うので注意。

### 感じたこと
- 略語の元の英語（cd = change directory など）や、対になる組（mkdir↔rmdir、cp↔mv、chmod↔chown）を意識するようになり、ただ暗記するより定着した。
- `&` と `&&` のように見た目が似て意味が違う記号は、表にして並べると違いがはっきりした。
- Markdown の表で `|` を `\|` とエスケープする必要があるなど、Qiita 投稿を通じて記法の細かい点も覚えられた。
