### 分かったこと

- Network パネルでは、ページを開いたときにブラウザがどのファイル（HTML / CSS / JS / 画像 / API）をどの順番で取りに行っているかが見える。ステータスコードや読み込み時間もここで確認できる。
- Cursor のデバッグ機能は、ブレークポイントで処理を止めて、その時点の変数の中身を見ながら1行ずつ進められる。`console.log` を仕込んで消す、を繰り返すより効率がいい
- `var` / `let` / `const` の違い。`var` は再宣言できてしまうので、基本は `const`、再代入が必要なときだけ `let` を使う
- `==` は型変換してから比較、`===` は型も含めて比較する（`!==` も同様）。基本は `===` を使う
- 数値と文字列の演算は、`+` だけ文字列連結になり（`1 + "1"` → `"11"`、型は string）、`-` `*` `/` は文字列が数値に変換されて計算される（`1 - "1"` → `0`、`1 * "1"` → `1`、`1 / "1"` → `1`、いずれも型は number）
- `typeof null` は `"object"` と返ってくる。これは JavaScript 初期からのバグが仕様として残っているもので、null かどうかの判定は `typeof` ではなく `=== null` で行う
- `if` の条件では `false` 以外にも `0`、`""`、`null`、`undefined`、`NaN` が偽として扱われる。
- `forEach` は配列の各要素に対して関数を実行する。`for` 文と違って `break` で途中で抜けられない。

- Cursor のデバッグツールは前回触ったときはよく分からなかったが、今回ブレークポイントと変数の見方がつながって、ようやく「何のためにあるのか」が腹落ちした

- `1 + "1"` だけが `"11"` になる挙動は、知らずに書くとバグの原因になりそう。演算の前に型を意識する癖をつけたい
