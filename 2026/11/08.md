### 分かったこと

**配列の map**

- `map` は「配列の全部の要素に同じ処理をして、新しい配列を作る」もの
- `map` の中で `console.log` を使うと、表示はされるが新しい配列の中身は `undefined` になる。配列を作りたいわけではないなら `forEach` を使う

**JSON**

- `JSON.stringify` は配列やオブジェクトを「文字列」に変える。サーバーに送るときに使う
- `JSON.parse` はその逆で、文字列を配列やオブジェクトに戻す。サーバーから受け取ったときに使う

**分割代入**

- 配列の分割代入は、`const [a, b, c] = 配列;` と書くと、前から順に a・b・c に入る
- `const [a, b = "初期値"] = 配列;` と書くと、配列に2つ目がないときだけ `"初期値"` が入る。配列にあればそちらが使われる
- オブジェクトの分割代入は、`const {drink2} = drinks;` と書くと、`drinks.drink2` の中身が `drink2` という変数に入る。順番ではなく名前で対応する
- オブジェクトの中身の取り出し方は3つ。`drinks.drink2`、`drinks["drink2"]`、分割代入してから `drink2`。結果はどれも同じ
- `...` は書く場所で名前が変わる。`const {a, ...rest} = obj;` のように左側に書くと「残りをまとめる」（レスト構文）、`const copy = {...obj};` のように右側に書くと「中身を広げる」（スプレッド構文）

**モジュール**

- `import` / `export` を使うと、別ファイルに書いた関数を読み込める
- 使うには `package.json` に `"type": "module"` を書く必要がある

**Promise（非同期処理）**

- Promise は「時間のかかる処理が終わったら結果を渡す」という約束のこと
- JavaScript は時間のかかる処理を待たずに次の行に進む。だから「終わったらこうしてね」を先に書いておく必要がある
- 「終わったらこうする」を `then` に、「失敗したらこうする」を `catch` に書く
- Promise には3つの状態がある。待っている最中（pending）、成功（fulfilled）、失敗（rejected）。一度成功か失敗になったら変わらない
- `then` は `.then().then()` とつなげて書ける。これを Promise チェーンと呼び、「Aが終わったらB、Bが終わったらC」と順番に処理できる
- 前の `then` の中で `return` したものが、次の `then` に渡される。`return` を忘れると次に何も渡らない
- `catch` はチェーンの最後に1つ書けばいい。途中のどこで失敗しても、最後の `catch` に飛んでくる
- `Promise.all([A, B, C])` は、A・B・Cを同時に始めて、全部終わったら `then` に進む。結果は配列で返ってくる
- `Promise.all` は1つでも失敗すると、全体が `catch` に飛ぶ
- チェーンは「1つずつ順番に」、`Promise.all` は「全部いっぺんに」。1秒かかる処理が3つあるなら、チェーンは3秒、`Promise.all` は1秒で終わる

| | 実行のしかた | 使う場面 |
|---|---|---|
| チェーン（`.then().then()`） | 直列：前が終わってから次 | 前の結果が次に必要なとき（ログイン → ユーザー情報取得 → 注文履歴取得） |
| `Promise.all` | 並列：全部同時に始めて全部待つ | 互いに関係ない処理をまとめて待つとき（商品一覧とお知らせを同時に取得） |

- `await` は「Promise が終わるまで待って、結果を変数に入れる」書き方。`then` と同じことを、上から下に読める普通のコードのように書ける
- `await` は `async` を付けた関数の中でしか使えない。失敗したときは `catch` の代わりに `try` / `catch` で囲む
- `await Promise.all([...])` と書くと、同時に実行して全部待ち、結果を配列で受け取れる

### 感じたこと

- オブジェクトを配列と同じように番号で取り出そうとして `undefined` になり、しばらく原因が分からなかった。配列は「番号で取る」、オブジェクトは「名前で取る」と役割が違うことを、手を動かして間違えたことでようやく区別できた
- 分割代入は、今日やった3行のコードでは使う意味が見えなかった。同じプロパティを何度も使うときや、関数の引数で受け取るときに楽になるものだと聞いて、「今は読めればいい」と割り切ることにした
- `...` を全部「スプレッド構文」だと思っていたが、左側に書けばレスト構文だと知った。同じ記号でも場所で名前と意味が変わるので、日報に書くときは正確な名前を使うようにしたい
- Promise チェーンと `Promise.all` を同じファイルで動かしたら、`Promise.all` の3つが1秒後にまとめて出て、チェーンは1秒ずつ順番に出た。「直列」と「並列」の違いを実行結果で見られたのが一番分かりやすかった
- 全角の「）」を打ってエラーになった。エラー行に間違いが見当たらないときは全角文字を疑う、と覚えておきたい
